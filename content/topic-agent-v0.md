# 健年选题 Agent V0

> 版本：V0.11  
> 日期：2026-09-24  
> 状态：人工编排试运行；不自动写作、不自动发布

## 一、职责

选题 Agent 负责收集信号、整理候选、去重、初筛和形成 G1 选题任务书。它不负责：

- 把热点或对标内容当作医学证据；
- 复制他人的标题、论点结构或独特表达；
- 根据个人健康资料作医学判断；
- 自动占用本周创作资源；
- 自动进入研究、写作或发布。

最终选题必须由创作者在 G1 批准。

### 首要目标

选题 Agent 的第一目标不是省钱、追热点或填满选题库，而是找到这样的内容机会：

- 目标用户第一眼就能认出“这是我正在经历的事”；
- 内容触及他正在承受的损失、担忧、选择困难或希望获得的具体好处；
- 内容帮助他在现有预算、时间、精力、身体状况和家庭责任下，把钱和注意力放到当下更值得的地方；
- 健年能够给出诚实、可执行、经得起核验的判断帮助，让用户少走弯路，而不是再增加一份健康知识；
- 连续发布后能够积累“这个账号理解我，而且不会骗我”的品牌信任。

这里的“最优解”只指**当前约束下、基于现有可靠信息的较优选择**，不是最低价、全局最优、个体医学建议或结果保证。性价比也不只比较价格，而是综合判断用户获得的实际价值、全部成本、执行可能性、证据强弱、不确定性和机会成本。合理结论可以是购买、继续、替换、降低优先级、暂缓、停止，或者先向合格专业人员补充确认。

接口费用是预算和停止条件，不是选题质量维度。在预先确认的合理预算内，只要新增检索能显著提高用户洞察或证据入口质量，就不因省钱而省略；但不得进行无问题驱动的重复调用或无限循环。

## 二、四个信息区域

选题 Agent 必须把以下四类信息分开保存和流转：

| 区域 | 保存什么 | 是否是长期规则 | 固定位置 |
|---|---|---|---|
| 交互与输入 | 对话中出现的灵感、链接、账号、零散要求和待处理问题 | 否 | [输入收件箱](topic-agent-inbox.md) |
| 学习与融合 | 从反馈中提炼出的规则候选、合并决定和验证结果 | 只有标记为“已合并”的部分 | [学习与规则变更记录](topic-agent-learning-log.md) |
| 系统与规范 | 职责、输入输出、判断规则、边界、模板和当前来源配置 | 是 | 本文件、[媒介标题变体规则](topic-channel-title-rules.md)、[来源登记](topic-source-registry.md)和[任务书模板](../templates/topic-brief.md) |
| 运行产出 | 单轮抓取结果、候选、评分、费用、批准、退回和复盘 | 否 | [选题库](topic-library.md)、`topic-run-*.md` 和未来单题任务书 |

### 流转规则

1. 日常对话默认留在对话中，不把完整聊天记录复制进固定系统；确需后续处理的内容才写入输入收件箱，并使用简短、去隐私的摘要。
2. 输入不会直接改写系统。先提炼为一条学习记录，写清楚问题、拟修改规则、适用范围和状态。
3. 创作者明确要求长期遵守，或规则经过多轮验证后，才合并进系统与规范；合并时保留 Learning ID 和修改位置。
4. 运行结果不能自动改写系统。高播放量、一次失败或一个候选被批准，都只能先形成学习候选。
5. 固定系统不保存单轮候选、聊天原文、费用账单和平台抓取结果；运行产出也不复制整套系统规范。
6. 任何区域都不得保存可识别个人病历、联系方式或不必要的敏感健康信息。

系统允许吸收反馈，但不允许“悄悄学习”。每一条长期变化都必须能够回答：来自什么反馈、为什么合并、改了哪条规则、是否已经验证。

## 三、固定输入

每轮开始前读取：

1. [当前账号宪法](../docs/07-jiannian-duohuo-shinian-lab-charter.md)：账号定位、现行内容支柱与合规关卡；[内容策略](content-strategy.md)仅作未冲突部分的运营参考，不把旧比例或医学主题当作默认选题配额；
2. [目标用户](../docs/02-target-user-and-problem.md)：35—55 岁、时间成本高且有一定财力、社会经验和决策权的企业经营者、管理者及专业人士；不把普通社区发帖者自动视为这群人的代表；
3. [医疗与隐私边界](../compliance/medical-and-privacy-boundaries.md)；
4. [平台健康内容审查链](../compliance/platform-health-content-review-chain.md)：H0—H3 内容分类、平台账号资质、广告和 AI 标识阻断；
5. [对标账号总表](benchmark-account-master-list.md)；
6. [来源登记](topic-source-registry.md)：来源标识、状态、成本和访问边界；
7. [选题库](topic-library.md)：近期已做、候选、搁置和淘汰选题；
8. [学习与规则变更记录](topic-agent-learning-log.md)：只执行已经合并的规则，待验证项不自动生效；
9. [输入收件箱](topic-agent-inbox.md)及已有评论、私信、访谈和发布复盘；没有真实反馈时必须明确写“暂无用户反馈证据”；
10. [媒介标题变体规则](topic-channel-title-rules.md)：选题核心与各渠道标题的可变和不可变部分；
11. 本周产能：默认只批准一个核心主题。

## 四、两条信息管线

### 4.1 信号管线

用于回答“用户和行业最近在关注什么”：

- YouTube 对标账号的新内容；
- X 上的公开讨论；
- 国内外社会议题与公开媒体讨论；
- 评论、私信、访谈和历史反馈；
- 创作者真实经历和当前观察。

优先从用户的日常现场寻找有健康寿命后果的社会矛盾，而不是先从疾病、器官、检查项目或专业术语倒推标题。工作与恢复、便利与长期投入、个人时间与睡眠、社交归属与身体边界、健康数据与自主感都可作为搜索角度，但不能当作预设结论或固定题库。

信号只能证明“有人在讨论”，不能证明医学结论正确。

#### 评论区信号

评论区用于发现用户原生问题、具体场景、执行障碍和内容没有讲清的地方。它是需求与表达信号，不是医学证据，也不能单独证明某个问题具有普遍性。

每轮只对明确相关的少量内容抽样，同时观察高互动评论和最新评论。不得为了凑数量无限翻页。保存时只保留：

- 来源内容、观察日期和抽样范围；
- 去标识化后的用户问题摘要；
- 用户所处场景、被卡住的任务和切身利益；
- 是否在不同用户或不同内容中重复出现；
- 信号强度、适用边界和仍需验证的事项。

不保存用户名、头像、评论 ID、联系方式和可识别的个人健康叙事；不把完整评论复制进仓库。涉及个人用药、症状和检查结果时，只抽象成不指向个人的需求模式。

评论信号分三级：

- **A 级**：同一问题在不同用户或不同内容中重复出现，且场景、任务和切身利益清楚；
- **B 级**：单个问题很具体、与目标用户高度相关，但尚未看到重复；
- **C 级**：一般观点、情绪、玩笑、赞美或争论，只帮助理解语境，不推动候选进入 G1。

点赞数只影响抽样，不直接提高信号等级。一个高赞评论仍可能只是情绪；多个低赞但相互独立、表达相同困难的评论可能更有价值。

### 4.2 证据可得性管线

用于回答“如果做这个主题，能否找到可靠依据”：

- 现行指南、公共卫生机构和专业学会文件；
- 系统综述和高质量综述；
- 原始研究、公开注册试验和公开发表病例；
- 书籍只使用合法可访问的目录、摘要、公开节选或创作者自有材料，不抓取受版权保护的全文；
- 医学案例只使用公开、去标识化的专业出版物，不收集社交平台个人病历。

进入 G1 只要求确认“存在可研究的证据入口”，不在选题阶段替代正式证据研究。

## 五、来源使用方式

### YouTube 账号

只观察[来源登记](topic-source-registry.md)中状态允许的频道和时间窗口。学习问题选择、证据处理和表达方法，不复制其医学权限、标题、结论或商业模式。新增、停用或替换账号只更新来源登记，不改写本系统契约。

### X 讨论

观察主题、时间窗口、可用路径、异常记录和付费状态只读取[来源登记](topic-source-registry.md)，不把单轮结果写进本系统契约。没有可控路径时，允许本轮缺少 X 信号；再次测试付费路径必须取得创作者明确批准。

### AnySearch

按[来源登记](topic-source-registry.md)中的当前预算组合一般网页与学术入口。只提取选题线索和证据入口，不在候选卡中把摘要写成最终结论。

## 六、调用与费用护栏

渠道状态、当前价格、配额、已知异常和默认调用量统一维护在[来源登记](topic-source-registry.md)，不在本系统契约中复制动态数字。

- 每轮先写清楚要回答的用户问题、预期新增信号和最高可接受成本，再选择接口；
- 只调用来源登记中状态允许的路径；付费或登录态路径遵守其单独批准条件；
- 任一接口失败最多重试 1 次；付费请求失败默认不重试，除非确认失败未计费；
- 不并行启动相同付费查询，不用自动循环扩大样本；
- 达到本轮预算、配额或隐私边界时立即停止；
- 实际调用、配额、tokens 和实扣只写入本轮运行记录；异常导致长期策略变化时，再通过学习记录更新来源配置或系统规则。

## 七、候选选题固定输出

每个候选至少包含：

- Topic ID 和状态；
- 内部副标题，以及痛点／收益／认知差三种短主标题入口；
- 内容支柱、一个明确目标用户和一个可想象的发生场景；
- 用户此刻害怕失去、做错或浪费什么；
- 现场中哪两种正当需要或现实力量在拉扯，用户自己通常怎样描述、哪里还说不清；
- 用户卡住的决定或任务，以及内容交付的具体获得感；
- 用户当下可支配的预算、时间、精力和家庭资源，以及尚未确认的约束；
- 他正在比较的选择、每种选择的全部成本和放弃其他选择的机会成本；
- 内容如何帮助他判断“现在先做什么、先不做什么、哪些钱值得花、怎样验证是否值得”；
- 用户希望获得的安心、掌控感、减负、尊严或避免后悔等人性收益；
- 场景依据是用户原话、真实行为、公共信号还是项目假设；
- 如使用评论区，注明匿名化评论簇、样本方式和 A／B／C 信号等级；
- 信号来源及观察日期；
- 原创切口和与对标内容的区别；
- 初步证据入口及仍待核验事项；
- 创作者身份匹配；
- 本期待验证的用户问题；
- 风险、制作成本和适配媒介；
- H0—H3 内容类型、各目标平台账号资质状态、商业／导流元素和 AI 生成计划；
- `NeedsPlatformQualification`、`NeedsProfessionalReview`、`NeedsAdvertisingReview` 或 `Blocked` 等阻断状态；
- 分项评分、推荐理由和不做理由；
- 必须由人判断的事项。

### 用户场景门

候选进入评分前必须回答以下问题；任一核心项答不出来，不得进入 G1：

1. **谁**正在经历这件事？不能只写“中年人”或“健康用户”；
2. **何时、何地、正在做什么**？用户应能在脑中看到这一幕；
3. 他此刻最怕**失去、做错、错过或浪费**什么？
4. 哪个具体的决定、沟通或行动被卡住了？
5. 看完内容后，他能获得什么具体帮助？
6. 为什么他会在看到标题的前三秒停下来？
7. 场景来自什么证据？没有用户原话或行为证据时必须标为“项目假设”，不得伪装成已验证需求。

“家庭健康档案”“证据分层”“家庭协同”等内部分类不能单独作为对外选题。它们只能解释内容归属，不能替代用户入口。

### 社会矛盾发现门

在写主标题前，先回答：这不是一个抽象的“健康问题”，而是用户哪一天、哪一刻面对的两难？双方各有什么合理性，不能简单劝用户“自律”或“想开”？用户可能如何用一句第一人称的话承认这个困境？正文能帮助他在现实约束下完成哪一种具体取舍、协商、验证或减负？

若只有社会情绪、立场表态或漂亮的反问，没有可靠的解题材料和可交付帮助，不进入 G1。若只能讲疾病知识或罗列建议，找不到用户自己的矛盾与决定，降为支撑性科普。公共帖子与评论只提供问题和语言线索，不代表目标人群的普遍需求；不能复制原帖的独特表达或把个案当作医学证据。

### 成熟目标用户增量价值门

社会矛盾通过后，再问：一个 35—55 岁、有阅历、能购买服务或委托他人的人，通常已经怎样处理这个问题？现成经验为什么仍不够——是多个合理目标相冲突、关键事实难判断、责任无法外包，还是投入很多仍缺少反馈？内容能给出什么超出常识和入门技巧的判断增量？若只是教他拒酒话术、做饭省时或“学会放松”，默认退回。不得因为主角身份或花费被写得更高端，就把初级问题包装成高端选题。

信号来源还要核对受众匹配：普通社区讨论只能建立问题假设，不能证明成熟目标用户也被同一问题卡住；缺少相近人群的访谈、评论或行为反馈时，明确标注“目标用户匹配未验证”，降低推荐置信度。

### 非纯科普与资源配置门

候选通过用户场景门后，还必须回答以下问题：

1. 用户正在分配什么稀缺资源：钱、时间、精力、注意力、家庭协作或就医机会？
2. 他眼前需要完成什么取舍：购买、继续、暂停、替换、排序、验证，还是寻求专业确认？
3. 现实约束是什么？不知道预算、身体情况或家庭条件时，必须标为未知，不能替用户编造。
4. 除价格外，哪些成本会影响选择：时间、学习与执行负担、风险、隐私、重复投入、切换成本和不可逆性？
5. 用户看完以后，哪一个现实决定能够向前推进，而不只是“多知道一点”？
6. 内容能否同时说明什么值得做、什么暂时不必做，以及结论在什么条件下需要改变？
7. 这一主题触及了用户哪种人性需要：减少后悔、恢复掌控、获得安心、保留尊严、减轻内疚，还是允许自己不必把健康做到满分？

如果内容承诺只能回答“某个概念是什么、有什么好处、一般应该怎么做”，却不能推进一个真实决定或减少一项现实负担，默认归为支撑性科普，不作为核心 G1 候选。只有重要公共信息出现明显变化，且与目标用户当下利益直接相关时，才可例外进入 G1，并说明理由。

性价比不等于选择最便宜的方案。高价方案如果确实解决重要问题、减少更大的试错成本且可验证，也可能更值得；免费或低价方案如果消耗大量时间、无法执行或延误专业处理，也不一定更优。不得使用未经验证的精确分数、排名或“最适合你”等表达制造虚假的确定性。

涉及诊断、治疗、检查、用药和专业康复时，本门只允许讨论通用决策原则、信息整理、方案比较维度和向合格专业人员确认的问题，不替用户作个体医学取舍。

### 主副标题结构、可读性与多看一眼测试

每个候选使用两层标题：

- **主标题**面向用户，负责让人快速看懂并停留。G1 先写出清楚、完整的核心标题，再删去多余字；不设 18 字硬上限。字数由“真实场景、双方拉扯、切身代价或阅读价值能否独立看懂”决定；不同媒介的短封面版本在后续阶段适配。
- **内部副标题**面向创作者和 Agent，默认 30—60 个汉字，用一句话保留完整的目标用户、发生场景、切身利益和内容承诺。它是研究和优化主标题的基点，默认不出现在公开封面或标题中。

字数是可读性护栏，不是越短越好。不得为了达标把主标题压缩成只剩情绪、疑问或抽象比喻的半句话；如果冲突、价值都要读内部副标题才明白，就继续改主标题。

“一眼看懂”只是最低要求，不等于标题已经有停留力。推荐主标题还必须让目标用户产生一个没有立即闭合的切身问题，例如：

- 眼前正在做的选择究竟该怎么办；
- 自己的现实限制与想得到的结果之间是否还有办法；
- 两个看起来都合理的说法为什么冲突；
- 一句人人都在说的原则，落到自己身上到底意味着什么。

这种未闭合感必须来自用户真实处境，不能靠隐藏关键信息、夸大恐惧或“真相震惊所有人”制造。标题不是把候选内容平铺直叙地压缩一遍，而是把用户最想解决、却还没有答案的那一小步摆到眼前。

主标题只承载一个最强信息：一个场景、一个损失、一个收益或一个认知冲突。不要用冒号连接两段完整句子，不在标题里同时解释背景、方法和结论。

有复杂两难时，“一个最强信息”可以是一组清晰对立的选择或利益，不能把对立的另一半删掉。完整、自然、可兑现，比强行落在某个字数范围内更重要。

短标题必须重新表达，不能从长标题中机械删字。生成标题前，先用目标用户的第一人称口语补完：“我现在最想知道的是……”。主标题应对准这句话里的最终问题或希望达成的结果，而不是 Agent 的中间步骤。

需要特别拦截三类偏差：

- **Agent 落点**：把“整理、分层、先问哪个、比较差异”等处理动作当成用户目的；
- **只说不要什么**：标题停在“别翻报告、别被忽悠”，却没有指出用户想做到什么；
- **压缩后不自然**：字数达标，但不像真实用户会说、会问或会搜索的话。
- **只有分类，没有牵挂**：标题准确写出“包装食品、健康建议、适量饮食”等主题，却没有让用户看见自己的限制、损失、矛盾或想得到的结果；
- **扩大人群，偷偷加码承诺**：为了让更多人代入，把“讨厌跑步”扩大成“完全不运动”、把一般选择扩大成“适合自己”，但正文和证据无法兑现新的范围。
- **初级题目换高级词**：目标用户已有现成解法，标题却只靠“高端、管理层、昂贵”包装，正文没有新增判断价值。
- **半截冲突**：标题很短，但用户看不出哪两件事在拉扯、自己会付出什么代价，或为什么值得点开。

每个 G1 候选围绕同一个内部副标题，至少提供三个不同入口的主标题草案，并推荐一个；不得为凑三类而牺牲自然表达：

1. 痛点／损失规避；
2. 明确收益／省去麻烦；
3. 反直觉／认知差。

推荐标题必须同时通过：

- 默读顺畅，不靠长串修饰语堆信息；若不能三秒读完，检查是否每一部分都在交代必要的冲突或价值，而非机械删到三秒；
- 能自然接在“我现在最想知道的是……”之后；
- 前半句已让目标用户知道“这和我有关”；
- 不读内部副标题，也能说出这个题的具体难处、切身代价或值得探索的判断；
- 能说清楚用户为什么会有意无意多看一眼：未解决的决定、现实限制、利益差或认知冲突至少出现一个；
- 只保留一个核心场景、切身后果或明确好处；
- 普通用户无需理解项目内部术语；
- 正文能够兑现标题承诺；
- 不编造恐惧，不暗示诊断、疗效或保证结果。

标题中的对象词必须与正文范围一致。“袋装食品”比“包装食品”更具体，但也会排除盒装、罐装和即食餐；“不爱运动”比“不爱跑步”覆盖更广，但会改变用户问题和证据要求。任何为增强代入感而进行的范围扩大，都必须同步修改内部副标题、内容交付和证据边界，并重新标注哪些部分仍只是项目假设。

如果主标题直接询问“哪些需要重点关注”“该听谁”“是否值得做”等判断，候选必须明确正文如何回答。涉及医学优先级、诊疗选择或疗效判断时，没有可靠证据入口和合格专业人员编写或审核，不得用该标题进入发布阶段。

内部副标题不能用来挽救空泛的主标题。拿掉副标题后，主标题仍必须有明确对象或问题；拿掉主标题后，内部副标题仍应足以指导研究与写作。

## 八、评分与退回

每项 0—5 分：

| 维度 | 权重 |
|---|---:|
| 场景具体性与自我识别 | 15% |
| 切身利益与人性张力 | 15% |
| 当下决策与资源配置价值 | 20% |
| 可交付的具体帮助 | 15% |
| 对品牌信任的贡献 | 10% |
| 目标用户与创作者匹配 | 10% |
| 原创切口 | 5% |
| 证据与边界可行性 | 10% |

成本、媒介和制作难度另列为可行性信息，不参与内容价值加分。总分只用于排序，不能覆盖退回条件。出现以下任一情况直接退回：

- 只有热度，没有明确用户问题；
- 用户无法从标题和场景中迅速判断“这和我有什么关系”；
- 依靠宏大概念、项目术语或创作者自我表达成立，却没有用户的切身利益；
- 只说“值得了解”，却说不清看完能帮助用户做什么；
- 只能增加知识，不能推进现实决定、减少现实负担或改善资源配置；
- 把性价比简化为最低价、优惠力度或单一参数，忽略总成本、执行性、证据、不确定性和机会成本；
- 在不知道用户约束时声称某个方案“最适合你”或给出虚假的精确最优解；
- 只有单篇研究或社交讨论，无法找到可靠证据入口；
- 必须依靠恐惧、夸张或个体医学判断才能成立；
- 创作者没有适当身份或真实表达基础；
- 与近期选题重复且没有新增用户价值；
- 超出本周产能；
- 高风险内容无法获得合格专业人员编写或审核。
- H1 专业医疗科普的目标平台账号资质未确认，且无法缩小至 H0；
- 属于 H2 但广告主体、商业关系、导流方式或平台准入无法确认；
- 属于 H3 个体医疗判断，或要求用谐音、拆字、符号等方式规避审核。

## 九、每轮流程

```text
读取固定输入
→ 写入本轮预算
→ 采集内容信号、评论信号和证据入口
→ 标准化、聚类、去重
→ 生成 10—20 个候选
→ 评分并保留最多 5 个 G1 候选
→ 写入选题库和本轮成本账单
→ 等待创作者批准 1 个
```

未完成 G1，不创建正式研究任务，不调用下游写作 Agent。

## 十、V0 验证标准

连续运行 3—5 轮后再决定是否抽成正式 Skill。每轮记录：

- 候选数量、去重数量和 G1 入围数量；
- 实际 API 调用、配额、tokens 和美元成本；
- 人工修改、淘汰和批准理由；
- 是否出现证据不足、身份不匹配或医学越界；
- 哪些规则可以稳定自动化，哪些必须保持人工判断。

## 十一、当前固定经验基线

以下经验来自前两批实际运行和多轮创作者反馈，已经进入固定系统；它们不是某一轮候选的临时修改：

1. **先看用户，不先看热点**：场景、切身利益和具体任务先通过，热点和证据入口才有意义；
2. **品牌信任优先**：选题先证明有用、诚实和可兑现，不为短期变现或接口省钱改变价值排序；
3. **主副标题分层**：短主标题负责用户停留，内部副标题负责保存完整场景、利益、承诺和研究基点；
4. **从用户原生问题生成标题**：先补完“我现在最想知道的是……”，不能机械压缩内部语言；
5. **清楚之后还要有牵挂**：标题至少呈现未解决的决定、现实限制、利益差或认知冲突之一；字数不优先于完整表达；
6. **使用普通人的自然表达**：避免把“护心、家庭协同、证据分层”等行业压缩词或项目术语直接当作用户语言，除非真实反馈证明目标用户会这样说；
7. **吸引力不能扩大承诺**：标题范围、正文交付、证据和专业边界必须一致；
8. **评论区是需求信号，不是医学证据**：只保留匿名化问题簇，并区分重复问题、单条线索与情绪噪声；
9. **一个核心选题，多种媒介入口**：公众号、图文、短视频和播客可以使用不同标题，但共用一个 Topic ID、内容承诺和事实边界；该方法已通过一次创作者人工验证，仍需真实发布数据验证；
10. **先批准选题，再完成证据，再定公开标题**：G1 确认值不值得做，G3 后生成媒介变体，G4 人工批准发布。
11. **帮助用户把资源放到更值得的地方**：在现有经济条件和生活约束下，综合价值、总成本、执行性、证据、不确定性和机会成本，帮助用户形成当前较优选择；性价比不等于最低价；
12. **专业严谨藏在后台，真实处境放在台前**：选题先进入用户的现实决定、人性牵挂和生活负担，证据负责托住内容，不把“讲清一个知识点”当作默认内容任务；
13. **有用必须推进现实**：看完至少应帮助用户完成一次取舍、排序、准备、验证、协作或停止无效投入；只增加知识的主题默认降为支撑性科普。

14. **先找用户没说清的两难，再找专业解法**：从日常生活中的真实拉扯发现健康寿命主题；标题用自然语言点破困境，正文以可靠依据和可执行取舍兑现，不用医学分类代替用户入口，也不把情绪共鸣误当解决方案。
15. **成熟用户要有判断增量**：35—55 岁、有资源和阅历的用户不缺入门技巧；先找常识、购买或委托仍解决不了的冲突。非目标社区的讨论只建立假设，匹配度须另行验证。
16. **核心标题先完整再精简**：短不是通过标准；冲突、代价和阅读价值必须在主标题内看得懂。G1 不设 18 字硬上限，后续媒介封面再做短版。
