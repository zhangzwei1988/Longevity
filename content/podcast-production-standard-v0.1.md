# 健年播客生产规范 V0.1

> 日期：2026-08-08
> 状态：内部试运行；待真实 TTS、发布与听众反馈验证
> 主平台：小宇宙
> V0 形式：8—15 分钟单人解释型节目
> 制作方式：组织稿 → TTS 纯净稿 → 外部 TTS → 人工审听 → 人工发布

## 一、目标与边界

本规范把 `G3Locked` 的统一内容包和 `CreatorConfirmed` 的叙事底稿，转化为有鲜明人格、适合声音传播、可交给 TTS、可在小宇宙完整发布和审核的播客生产包。

播客 Skill 负责媒介表达与生产组织，不重新研究事实，不改变证据强度，不批准医学结论，不调用 TTS API，不自动发布。

公众号文章不是播客母稿。播客同时读取统一内容包和叙事底稿，利用声音呈现判断过程、陪伴感和人格。

## 二、输入门

正式制作要求：

- 统一内容包为 `G3Locked`，包含允许平台、内容类型、CTA、专业审核和 AI 披露要求；
- 叙事底稿为 `CreatorConfirmed`，并明确依赖的统一内容包版本；
- 本期只解决的问题、目标听众、预计时长和期望状态明确；
- 创作者经历、合成场景、第三方声音、音乐和图片均有明确授权边界；
- TTS 使用的声音身份、授权来源和披露方式明确；
- 小宇宙账号资质和发布日平台规则进入检查清单。

未锁定输入只允许创作者明确要求的 `DesignTrial / NotReleaseReady`。缺少会改变事实、结论强度、适用人群、行动方向或责任归属的输入时，退回写作 Agent。

## 三、先冻结一条播客任务

先判断主题是否真的适合音频。至少应有一个值得陪伴展开的困境、判断过程、现实冲突或创作者复盘；只有少量结论和清单时，优先做图文或短视频，不把三分钟信息灌水成十五分钟播客。V0 维持低频长期人格资产定位，不要求每个统一内容包都生成播客。

开始写稿前，先冻结：

- 目标听众正在经历的具体时刻；
- 本期只完成的一个任务；
- 听完能复述的一句话；
- 听众可以做的一个低风险动作；
- 必须保留的限制；
- 本期不讲的内容；
- 一个中段洞察高峰；
- 一个峰终收口；
- Show Notes 和插图分别承担什么补充任务。

信息很多时拆成系列，不通过加快语速、删限制或堆清单解决。

## 四、播客人格引擎

播客默认把账号人格变成四个可听见的动作，而不是四个抽象形容词。

### 4.1 护短：先站回听众一侧

在拆误区、消费或错误判断前，先解释普通人为什么容易相信、为什么会犹豫。使用“我先替你问一句”“这真不怪你难判断”一类平等表达，不把听众写成需要被教育的人。

### 4.2 较真：替听众完成盘问

反复追问对象、依据、适用范围、成本、验收和责任。问题要逐层推进，不能只是连续反问。每一轮盘问之后给出信息或判断，不让听众一直悬着。

### 4.3 清醒：敢判断，也主动刹车

关键处可以锋利地下判断，但紧接着说明它能推出什么、不能推出什么。清醒不是每段都念免责声明，而是在结论最可能被误用的地方及时收边界。

### 4.4 自嘲：给复杂内容留呼吸

使用生活比喻、冷幽默、反差、轻微自我修正和经批准的创作者自嘲，降低说教感。每个大模块通常只留一到两个真正有效的“刺”。锋芒只对准空洞话术、逻辑漏洞和荒诞流程，不攻击用户、患者、老人、身体或未经核实的具体机构。

### 4.5 声音节奏

- 判断句短，解释句可以稍长；
- 问题之后留停顿，重要反转前后留呼吸；
- 使用回环、轻微重复和自然自我修正，不制造假口吃；
- 用语速和停顿区分“下判断、拆证据、收边界、给行动”；
- 一个自然段只承担一个主要声音动作；
- 不写成新闻播音腔、演讲腔或公众号朗读腔。

每期用四级刻度分配人格，不写含糊百分比：

- **主轴**：决定整集观察角度，并至少推动三个关键转折；
- **辅助**：在一到两个模块承担关系或解释任务；
- **点缀**：只出现一到两次，不抢信息；
- **禁用**：本期主动不使用。

通常只设一个主轴。四种人格同时拉满会让节目像在表演人设。

### 4.6 语言锤

每期除栏目名外，只选择一到两个语言锤自然出现，不机械集邮：

- “我先替你问一句”：从用户处境进入较真盘问；
- “这件事，先别急着信／做／买”：在证据或决策前主动刹车；
- “证据到哪儿，我们就把话说到哪儿”：收紧结论边界；
- “今天这份健康功课”：引出最后一个低风险动作或判断清单。

语言锤后必须有真正的信息交付，不能只作为口号。连续 3—5 期真实验证后，再决定哪些保留为长期声音识别。

### 4.7 声音指纹

V0 可以试验一个极短、可自行录制或明确授权的“翻纸＋落笔”声音，作为进入“今天这份健康功课”或片尾签名的提示。只出现一次，控制在不打断理解的范围内。

声音曲线默认采用：开场近、短、克制；盘问段稍紧；证据段放稳；高峰变慢而不是变吵；行动段清楚；收尾留白。停顿本身是设计，不用全程背景音乐填满。

不得使用心电监护、警报、救护车等制造医疗紧张感，也不得使用来源不明的音乐和音效。

## 五、固定品牌与声音识别

固定内容必须短，不能打断钩子兑现。

默认顺序：

```text
主题钩子
→ 本期承诺
→ 节目识别
→ AI 声音声明
→ 正文
```

节目识别默认使用：

> 这里是多活十年 Lab 的「今天这份健康功课」。

价值说明可在新节目阶段或确有需要时加一句：

> 专替忙人做健康功课，帮你少踩坑、少花冤枉钱。

TTS 版本默认加入清楚、简短的声明：

> 本期内容由多活十年 Lab 编辑，使用 AI 合成声音播讲。

不在每期口播完整品牌层级和创作者履历。若使用“我是某某”或第一人称真实经历，必须区分作者、叙述者与合成声音身份，并已有公开授权。

结尾先落下本期特有的记忆句，停顿后再选择一个已批准 slogan；同一期通常只使用一个 slogan。最终记忆句之后不再追加销售 CTA、长免责声明或资料清单。

## 六、结构选择

不要机械套一个模板。先根据任务选择最合适的结构，再保留共同的声音节奏。

### 6.1 决策拆解型

适合健康消费、检查、服务和现实选择：具体付款／行动时刻 → 真正风险 → 逐项盘问 → 责任错位高峰 → 判断框架 → 行动与边界。

### 6.2 说法审问型

适合流行观点和证据判断：一句流行说法 → 为什么诱人 → 它偷偷省略了什么 → 证据支持与不支持 → 更稳妥的说法 → 听众下一步。

### 6.3 困境陪跑型

适合忙碌、执行中断和家庭协同：具体生活场景 → 为什么反复卡住 → 最小有用框架 → 现实阻力高峰 → 一个可执行动作 → 何时交给专业人员。

### 6.4 创作者复盘型

只在经历已批准公开时使用：真实处境 → 当时如何判断 → 哪里走弯路 → 后来如何修正 → 哪部分只是个人经验 → 可供听众复用的原则。

不得用虚构经历或合成声音冒充个人见证。

## 七、开场与前一分钟

开场由“钩子＋立即兑现”组成。钩子可以使用具体决策时刻、真实冲突、常见误判、反差或用户原话式问题，但必须是本期真实价值的高密度表达。

每期先生成 3—5 个钩子候选，并记录：

- 它承诺什么；
- 正文在哪里兑现；
- 是否扩大人群、因果、风险、数量或行动；
- TTS 读出来是否自然；
- 与标题、摘要和结尾是否构成闭环。

前一分钟内让听众知道：这件事为什么和自己有关、这一集会讲清什么、节目是谁制作、声音是否由 AI 合成。禁止空悬念、疾病恐惧、虚假紧迫、疗效夸张和长品牌广告。

## 八、中段与高峰

每个段落必须增加场景、事实、证据解释、判断、限制、情绪变化或行动中的至少一项。段落之间使用问题、回扣、未完成判断或现实后果自然过渡，不使用“接下来第一点、第二点”贯穿整集。

高峰通常位于内容约 60%—75%，来源于：

- 一个前后承诺不一致的现实场景；
- 一个能重新定义问题的洞察；
- 一项与直觉相反但有证据支持的结论；
- 听众终于看见自己为什么反复卡住。

一集只保留一个主高峰。音乐、音效和提高音量只能辅助，不能制造本来不存在的信息价值。

## 九、峰终收口

结尾建议按以下顺序：

```text
回扣开场
→ 一个低风险动作
→ 必要边界
→ 可选互动问题
→ 本期最终记忆句
→ 停顿
→ 固定片尾或 slogan
```

不要总结所有知识点。最终记忆句应当短、可复述、脱离上下文仍不误导，并与开场形成闭环。必要来源和完整说明放入 Show Notes，但会改变结论的限制必须在音频中说出来。

## 十、TTS 双稿与生成说明

### 10.1 组织稿

组织稿保留每段任务、情绪、语速、重音、停顿、发音、Claim ID、来源、音乐和剪辑提示，用于制作和审核，不直接整体送入 TTS。

### 10.2 TTS 纯净稿

纯净稿只保留真正需要被说出来的文字，并按自然语义切成可独立重生成的段落。不得出现 Claim ID、链接、Markdown 标题、表格、括号制作指令或工作流状态。

生成前单独处理：

- 多音字、人名、机构名、药品／设备名和外语发音；
- 数字、百分比、年份、单位、缩写和网址的口语写法；
- 引语是谁说的，不能只靠引号区分；
- 每段情绪、语速、停顿和句尾走向；
- 需要保留或关闭的 TTS 服务商水印／元数据。

不默认模拟多人对话，不使用未授权声音，不用“真人没说过的话”冒充真人录音。具体 API 参数由后续 TTS 适配层处理，不写死在本规范中。

### 10.3 声音定标

首次选择 TTS 声音或更换模型时，先准备一段约一分钟的定标稿，同时包含钩子、反问、较长解释、冷幽默、数字、边界和收尾。用同一段文字比较候选声音的亲近感、较真感、停顿、中文发音和“播音腔”，不要直接用完整节目试错。

优先选择温暖、克制、像认真聊天而非新闻播报的声音。确认后记录服务商、模型、声音 ID、授权和版本；保持一个阶段内的稳定性。声音风格变化属于创作者需要确认的品牌变化。

## 十一、小宇宙发布包

### 11.1 文字资产

每期至少交付：

- 3—5 个单集标题候选和一个推荐项；
- 单集封面短标题；
- 2—4 句首屏摘要，先说用户价值；
- “你将听到”的 3—5 个具体问题或收获；
- 最终音频生成后填写的准确时间轴；
- 一份完整 Show Notes；
- 来源、延伸资料和必要说明；
- AI 合成声音声明；
- 一个自然互动问题；
- 可选的置顶评论或投票草案。
- 一条跨平台分享短文案。

时间轴不得根据组织稿伪造。先在 Run of Show 中写段落名，只有对最终音频完成审听后才填写准确时间点。

### 11.2 视觉资产

- 每期必须有一张单集封面；
- 正文插图默认 0—3 张，只有承担解释、对照、收藏或查阅任务时才制作；
- 适合时优先提供一张确定性排版的“健康功课单”；
- 精确中文、数字、来源和限制使用确定性排版；
- 图片记录来源、版权、AI／合成性质、Alt 文本和使用位置；
- 不使用通用器官、白大褂、医院蓝、黑金抗衰、恐惧画面或无关装饰图；
- 不重复制作小宇宙平台能够生成的分享图，只准备封面、插图和分享文案。

封面与插图的尺寸、格式和文件大小只记录发布日后台核验结果，不在长期规范中写死易变参数。

图片不得补充统一内容包之外的新事实。若没有可用视觉资产，状态为 `NeedsVisualAssets`，不能用提示词冒充已完成图片。

### 11.3 互动与边界

置顶评论和投票同样属于 G4 审查范围。不得邀请听众发送病历或在评论区寻求个体诊断；涉及商业、联系方式、链接或服务时重新进入广告与平台复核。

## 十二、最终音频审核

TTS 音频生成后必须审核实际文件，不以文字自检代替审听：

- 是否漏字、重读、错音、断句错误或情绪错位；
- 合成声音是否让作者身份、个人经历或专业责任产生误认；
- 音速、停顿、重音和情绪是否保留播客人格；
- 音乐、音效、响度、接缝和静音是否自然；
- 事实、数字、来源和关键限制是否被准确读出；
- AI 显式声明、文件记录和发布日平台标识是否完整；
- 最终时间轴是否与音频一致；
- 标题、摘要、Show Notes、插图和音频是否兑现同一承诺。

审核只能给出 `NeedsRevision / NeedsPlatformCheck / ReadyForHumanG4`，不能代替人工 G4。

## 十三、V0 学习

连续验证 3—5 个真实主题，记录：

- 最自然和最生硬的人格动作；
- 哪些句型被 TTS 读成播音腔；
- 钩子、品牌识别、高峰和收尾的退出位置；
- 错音、重生成和人工剪辑次数；
- Show Notes 首屏、时间轴和插图的实际使用反馈；
- 听众在评论中复述的判断是否准确；
- 有效问题、收藏／分享、完成收听和制作成本。

未经创作者确认，不把一次数据或一次修改静默写入固定规则。
