# 多活十年 Lab 内容系统行动计划与完整任务清单

> 日期：2026-07-31  
> 状态：当前执行清单  
> 适用范围：多活十年 Lab 的选题、研究、公众号长文、图文、播客、短视频、发布与复盘

## 一、文件目的

本文件回答两个不同问题：

1. **最小闭环行动计划**：怎样不等体系完美，先让一个真实主题完成从选题到复盘的全流程；
2. **完整任务清单**：要把内容系统建设到相对成熟、稳定、可持续，还需要完成什么。

本文件负责执行，不重新定义账号战略。上位依据为：

- [决策 0009：内容基本功优先，商业化从真实需求中生长](../decisions/0009-content-foundation-and-organic-commercialization.md)；
- [多活十年 Lab 内容策略](content-strategy.md)；
- [多领域内容生产 Harness 建设纲领](../docs/06-content-harness-charter.md)；
- [医疗与隐私边界](../compliance/medical-and-privacy-boundaries.md)；
- [健年平台健康内容审查链](../compliance/platform-health-content-review-chain.md)。

## 二、共同原则

1. 一次只推进一个核心主题；
2. 统一内容包是四种媒介共同的事实基准；
3. 公众号长文、图文、播客和短视频是四种不同的媒介翻译，不是相互复制；
4. 第一轮必须验证四种形式，长期运行不要求每周四种形式全部发布；
5. 先使用简单排版、固定机位和现有工具，不让设备、装修、模板和自动化阻塞发布；
6. 涉及医学专业结论而无法完成相应审核时，应缩小结论、改做权威资料翻译或停止发布；
7. 每轮必须留下耗时、返工、错误和用户反馈，否则不算闭环；
8. 不用播放量代替内容质量和真实用户问题。

# 第一部分：最小闭环行动计划

## 三、闭环目标

用一个真实选题，在建议 **10 个工作日、最迟 14 个自然日** 内完成：

```text
选题批准
  → 研究与证据包
  → 统一内容包草案与公众号母稿
  → 事实审核和统一内容包锁定
  → 图文、播客、短视频
  → 人工审核与发布
  → 用户反馈采集
  → 单期复盘和下一期决定
```

第一轮的目标不是证明内容一定受欢迎，而是证明：

- 能否把一个真实问题研究清楚；
- 四种形式能否保持事实一致、表达不同；
- 创作者能否在可接受的时间内完成；
- 哪些步骤最容易返工或越界；
- 用户是否产生收藏、转发、追问或具体问题表达。

## 四、第一轮范围锁定

开始前只确认以下事项，不继续扩展体系：

- [ ] 只选一个低至中风险、证据可得、创作者有真实表达基础的主题；
- [ ] 明确本期只回答的一个问题；
- [ ] 明确本期主要功能：吸引、信任、人格或互动，只选一个；
- [ ] 明确四种形式的最小规格；
- [ ] 明确发布渠道和人工审核人；
- [ ] 暂不建设完整视觉手册、自动化系统、大型选题库和复杂数据看板。

## 五、10 个工作日行动表

| 时间 | 动作 | 必须产物 | 过关条件 |
|---|---|---|---|
| 第 1 天 | 确定选题 | 1 页选题任务书 | 用户、场景、问题、价值、风险和不做理由清楚 |
| 第 2—3 天 | 研究与证据整理 | 研究问题清单、核心来源、证据与限制表 | 能说明哪些话能说、哪些不能说 |
| 第 4 天 | 起草统一内容包 | 统一内容包草案、公众号结构 | 核心结论、论点、来源、限制和行动能够逐项对应 |
| 第 5 天 | 完成公众号母稿 | 公众号长文 V1 | 能独立解决问题，不靠销售转折成立 |
| 第 6 天 | 审核并锁定事实 | 审核记录、统一内容包 V1 | 核心结论、来源、限制、动作和互动问题通过审核 |
| 第 7 天 | 完成图文 | 分页脚本、视觉方案和发布文案 | 不是长文截图，用户可快速理解并收藏 |
| 第 8 天 | 完成播客 | Run of Show、录音、简介与 Show Notes | 不是朗读文章，能体现思考过程和人格 |
| 第 9 天 | 完成短视频 | 脚本、镜头表、成片与字幕 | 开头承诺与实际内容一致，一条视频只做一件事 |
| 第 10 天 | 一致性审核、发布并启动反馈 | 四种成品、检查表、发布链接、反馈入口 | 无关键事实漂移；四种形式已发布或有明确停发原因 |

发布后在 **72 小时** 做快速复盘，在 **7 天** 做完整复盘。

## 六、四种形式的第一轮最小规格

### 6.1 公众号长文

- 一个具体困境；
- 一个核心判断；
- 一套可迁移框架；
- 必要的证据、限制和专业边界；
- 一个用户可以立即采取的低风险动作；
- 一个自然互动问题；
- 使用简洁排版，不等待完整视觉系统。

### 6.2 图文

- 1 张封面；
- 5—7 张内容页；
- 困境、误区、核心解释、判断框架、行动与限制至少各有明确位置；
- 只使用一套临时字体、颜色和版式；
- 保留来源和限制，不因分页而改变结论；
- 不使用通用 AI 卡片风作为完成标准。

### 6.3 播客

- 8—15 分钟单人节目即可；
- 开场说明为什么值得听；
- 中段讲清困境、判断过程、证据和限制；
- 结尾明确用户能带走什么、仍有什么不知道；
- 使用简单片头片尾，不等待完整声音品牌。

### 6.4 短视频

- 45—90 秒；
- 前 3 秒提出具体问题、冲突或价值承诺；
- 只讲一个核心结论；
- 使用固定机位、真人口播和必要字幕；
- 结尾提供一个动作或互动问题；
- 不等待复杂布景、动画和多机位剪辑。

以上规格只约束第一轮范围，不是永久平台标准。

## 七、推进保护规则

为防止完美主义使闭环停滞，第一轮执行以下规则：

1. **主题不扩张**：研究过程中出现的新问题进入候选池，不并入本期；
2. **模板不过度设计**：同一视觉问题最多比较两个方案，由创作者当日选择；
3. **形式不求同等重量**：公众号可以最完整，其他形式只完成各自的核心任务；
4. **到时交付可审版本**：超过时间盒时先减少装饰、长度和支线，不删除证据限制；
5. **风险不能降级处理**：医学、资质、隐私和事实问题不能为了按时发布而略过；
6. **无法审核就缩题**：如专业审核无法及时完成，改为低风险方法、个人过程或权威资料的准确转述；
7. **不临时开发系统**：第一轮用文件、清单和人工交接完成。

## 八、最小复盘表

第一轮结束必须回答：

- [ ] 计划耗时和实际耗时分别是多少？
- [ ] 哪一步返工最多，原因是什么？
- [ ] 哪些结论最难核验？
- [ ] 四种形式是否出现事实或边界漂移？
- [ ] 哪种形式最自然，哪种最消耗创作者？
- [ ] 哪一处表达带来了收藏、转发、追问或具体问题？
- [ ] 哪些互动只是泛泛点赞，哪些暴露了真实需求？
- [ ] 下一期保留哪三件事、修改哪三件事、停止哪一件事？
- [ ] 是否具备开始下一期的条件？

## 九、最小闭环完成定义

同时满足以下条件才算完成：

- [ ] 一个主题完成了选题、研究、统一内容包、制作、审核、发布和复盘；
- [ ] 公众号长文、图文、播客、短视频各完成一个可发布版本；
- [ ] 每个核心结论都能回到统一内容包和来源；
- [ ] 没有遗留的重大事实、专业边界或隐私问题；
- [ ] 已记录四种形式的耗时和返工；
- [ ] 已记录真实用户反馈或明确记录“暂无有效反馈”；
- [ ] 已形成下一期具体调整，不以“继续完善体系”代替行动。

## 十一、P1：连续运行后完善

以下事项在完成首轮后开始，通过至少 3—5 个真实主题逐步建设：

### 11.1 对标拆解

- [ ] 按能力模块选择对标，不寻找一个完整复制对象；
- [ ] 分别拆解证据翻译、研究生产、脚本结构、人格表达、视觉表达、评论互动和服务连接；
- [ ] 每条样本记录用户困境、开场、结构、证据、限制、行动和评论问题；
- [ ] 区分可迁移方法与依赖医生身份、团队资源或平台文化的部分；
- [ ] 将有效模式写入模板，将反例写入检查表。

### 11.2 发布与分发

- [ ] 明确各平台原生版本和轻量复用范围；
- [ ] 建立发布日历，但只承诺可持续频率；
- [ ] 定义标题、封面、正文、标签和发布时间记录；
- [ ] 定义评论回复、私信转访谈和敏感问题处理规则；
- [ ] 建立发布链接和素材归档；
- [ ] 不因某一条数据异常立即改变账号定位。

### 11.3 反馈与复盘

- [ ] 记录收藏、转发、完读／完播和高质量评论；
- [ ] 记录用户原话、具体问题和反复出现的场景；
- [ ] 区分泛流量、目标用户互动和真实需求信号；
- [ ] 记录每种媒介的生产耗时、返工次数和错误类型；
- [ ] 比较同一主题在四种形式中的表现与用户获得感；
- [ ] 建立保留、修改、停止三个复盘决定；
- [ ] 将有效反馈回流选题池、账号定义和模板；
- [ ] 商业化只在公开内容无法解决的问题反复出现后另立实验。

### 11.4 质量评估集

- [ ] 保存优秀成品样例；
- [ ] 保存人工修改前后对照；
- [ ] 保存夸大标题、证据不足、越界和跨媒介失真反例；
- [ ] 建立账号人格、用户价值、证据质量和媒介适配评分；
- [ ] 定期淘汰无效规则，避免规范只增不减。

## 十二、P2：稳定后再建设

只有在人工流程出现稳定、重复、低风险的负担后，才进入以下事项：

- [ ] 自动创建单期工作区；
- [ ] 自动传递已批准版本；
- [ ] 自动检查结构、缺失字段、来源和版本一致性；
- [ ] 自动生成审核队列和复盘汇总；
- [ ] 建立素材、版权和发布资产库；
- [ ] 建立可查询的用户问题与选题反馈库；
- [ ] 将稳定规则抽取到 Harness Core；
- [ ] 保留专业判断、品牌责任和最终发布的人工关卡；
- [ ] 用第二个真实账号验证通用性后再讨论规模化。

以下事项在当前阶段明确不作为目标：

- 自动发布；
- 大规模账号矩阵；
- 批量生成相似健康内容；
- 让生成系统自行判断医学结论；
- 为了展示自动化而增加重型工程。

## 十三、“比较完善”的完成标准

内容系统达到相对完善状态，不以文档数量判断，建议同时满足：

- [ ] 至少 5 个真实主题完成从选题到复盘；
- [ ] 四种形式均有经过真实发布验证的结构和样例；
- [ ] 账号级视觉锤和语言锤形成 V1，并能跨媒介保持家族相似性；
- [ ] 统一内容包能可靠支撑四种形式；
- [ ] 主要返工原因已识别，连续三期没有反复发生相同的职责争议；
- [ ] 生产耗时进入创作者可长期承受的范围；
- [ ] 没有严重事实、医学边界、隐私或版权事故；
- [ ] 已获得能够影响下一期选题或表达的真实用户反馈；
- [ ] 已明确哪些形式长期高频、低频或停止；
- [ ] 自动化只覆盖已经稳定、重复和低风险的步骤。

## 十四、当前唯一下一步

从候选方向中选择第一个低至中风险的真实主题，填写选题任务书并进入 G1。未完成第一轮复盘前，不继续扩建完整系统。
