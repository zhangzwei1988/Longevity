# 多领域内容生产 Harness 建设纲领

> 日期：2026-07-30
>
> 状态：指导纲领，当前有效；工程尚未开始抽取
>
> 当前首个验证实例：健年 Healthspan 旗下“多活十年 Lab”
>
> 适用范围：内容工作流设计、Agent 协作、质量控制、工程抽取与未来多账号复制

## 一、文件目的

本文件记录建设一套通用内容生产 Harness 的长期目标、详细需求、实施步骤、核心原则和阶段门槛。后续的流程设计、模板、Agent、自动化、工程实现和多账号复制，都应以本文件为上层指导。

本文件不是当前已经完成的系统说明，也不代表所有设计都已经过真实生产验证。当前正确顺序是：

1. 先为“多活十年 Lab”建立并跑顺第一套真实工作流；
2. 在实际生产中记录耗时、返工、错误、人工判断和用户反馈；
3. 识别反复出现、跨领域稳定成立的共性；
4. 将共性抽取为 Harness Core；
5. 将健康专业知识、品牌人格和平台表达保留在可替换的领域包、账号包和渠道适配器中；
6. 用第二个真实账号验证抽取是否成立，再逐步扩大复制范围。

本纲领承接以下当前有效文件：

- [当前上下文](00-current-context.md)；
- [决策 0009：内容基本功优先，商业化从真实需求中生长](../decisions/0009-content-foundation-and-organic-commercialization.md)；
- [多活十年 Lab 内容策略](../content/content-strategy.md)；
- [医疗与隐私边界](../compliance/medical-and-privacy-boundaries.md)。

如未来项目阶段或方向发生变化，应先更新重大决策，再判断是否需要修订本纲领。普通 Agent、模板和工程实现变化不应反向改写已经确认的项目原则。

## 二、长期目标

### 2.1 当前目标

为“多活十年 Lab”建立一套准确、克制、高效、创作者本人能够长期坚持的内容生产链路。确定选题后，以统一内容包为唯一事实源，先形成不绑定单一媒介的叙事底稿，再分别适配公众号、小红书图文、播客和视频，实现一次研究、多种媒介表达的“一鱼多吃”。

第一套工作流包含两个主要生产 Agent 和一组渠道 Skill：

1. 选题 Agent；
2. 写作 Agent；
3. 公众号、图文、播客和短视频等渠道 Skill。

除上述生产角色外，系统必须有独立于生产角色的质量控制、专业审核和人工批准机制。生产角色不能因为能够生成内容，就自动取得最终发布权。

### 2.2 长期目标

在第一套工作流稳定后，将中间共性抽取成一套可复用的 Harness 工程，用于建设不同专业领域、不同品牌人格和不同平台组合的内容账号。

未来新增账号时，不应复制一套相互独立、难以维护的工程，而应组合：

```text
通用 Harness Core
  + 领域知识包 Domain Pack
  + 账号定义包 Account Pack
  + 渠道适配器 Channel Adapter
  + 当期内容工作区 Episode Workspace
```

这套系统最终要规模化复制的是可靠的生产能力、质量控制方法和反馈闭环，而不是批量制造相似账号，也不是把未经验证的专业权威复制给 Agent。

## 三、最核心的点

### 3.1 统一内容包才是事实源

公众号文章是“多活十年 Lab”当前最先完成、用来打磨事实和表达的主内容形式，但通用 Harness 不应把公众号文章硬编码为所有账号的唯一事实源。

系统的唯一内容事实源应是“统一内容包”。它保存本期内容中不会因媒介变化而改变的语义核心：

- 目标用户与具体困境；
- 本期只解决的一个核心问题；
- 一句话核心结论；
- 关键论点与逻辑关系；
- 事实、来源、证据强度、适用范围和限制；
- 创作者的真实经历、观察与明确标注的个人观点；
- 用户可以采取的低风险动作；
- 必须由专业人员回答的问题；
- 禁止出现或不得推导的表达；
- 本期待验证的用户问题；
- 自然、克制的互动动作。

公众号、图文、播客和视频都是对统一内容包的不同媒介翻译。各 Agent 可以调整开头、顺序、长度、节奏、视觉和语言，但不得擅自改变核心事实、证据边界和最终导向。

统一内容包之后可以生成一份叙事底稿，作为跨渠道共享的表达源。它保存场景、冲突、人格、比喻、转折和可复用金句，但不保存新的事实权威。各渠道同时读取统一内容包和叙事底稿；发生冲突时统一内容包优先。任何已发布渠道稿都不得反过来成为其他渠道的事实源。

### 3.2 抽取流程，不抽取专业权威

可以通用化的主要是：

- 工作流状态；
- Agent 的输入输出契约；
- 内容对象和版本结构；
- 人工审核门；
- 质量评估框架；
- 返工、失败重试和审计记录；
- 多平台加工和资产管理；
- 发布后的数据、互动与选题回流。

不能直接通用化的主要是：

- 某一领域的专业结论；
- 对信息源可信度的具体判断；
- 领域特有的监管和资质要求；
- 创作者的真实经历、人格与责任；
- 某个账号已经获得的用户信任；
- 不同领域的商业边界和风险容忍度。

规模化复制的是生产系统，不是信任、资质和责任。

### 3.3 Agent 契约比 Prompt 更重要

每个 Agent 都必须写清楚：

- 输入是什么；
- 可以访问哪些上下文；
- 必须遵守哪些规则；
- 输出的固定结构是什么；
- 完成标准是什么；
- 哪些问题必须退回上一步；
- 哪些判断必须升级给人或专业人员；
- 不允许做什么；
- 谁对最终结果负责；
- 如何记录版本、来源和修改原因。

Prompt 是可替换的实现细节。稳定的对象、契约、审核门和评估标准才是 Harness 的长期资产。

### 3.4 质量和责任优先于吞吐量

系统不能以“每天生成多少条内容”作为首要成功标准。首要目标是：

- 事实准确；
- 来源可追溯；
- 证据和结论匹配；
- 不隐瞒限制与不确定性；
- 对用户有独立价值；
- 符合账号人格；
- 适合具体媒介；
- 不制造健康焦虑；
- 不越过专业与医疗边界；
- 创作者能够长期维持；
- 内容能够带回高质量问题和真实反馈。

### 3.5 真实运行先于通用抽象

第一套工作流允许保留健年特有的做法，不为了未来通用而过早增加配置、插件和复杂编排。只有一个规则在真实生产中稳定重复，并能证明与健康领域或多活十年 Lab 无关时，才进入 Harness Core 候选。

## 四、系统分层

### 4.1 Harness Core：通用控制层

负责所有领域都可能需要的通用能力：

- 工作流编排和状态流转；
- Agent 调用与任务交接；
- 内容对象、唯一 ID、版本和依赖关系；
- 人工批准、驳回和返工；
- 质量检查与评估；
- 运行记录、失败重试和恢复；
- 资产目录和发布状态；
- 用户反馈采集与选题回流；
- 权限、密钥、账号和数据隔离；
- 模型、Prompt、规则和配置版本记录。

Harness Core 不保存具体领域结论，也不假设所有账号都必须从公众号开始。

### 4.2 Domain Pack：领域知识与责任层

每个专业领域单独定义：

- 领域术语与概念关系；
- 权威来源白名单和来源优先级；
- 来源时效与更新要求；
- 证据等级和可接受的推理方式；
- 常见误解和禁止推导；
- 合规、监管和平台限制；
- 哪些内容可以由普通创作者完成；
- 哪些内容必须由合格专业人员编写或审核；
- 风险分级和升级条件；
- 领域专用的质量测试样例。

领域包不能只是向 Prompt 填入大量资料。知识必须能够追溯来源、识别版本、按需检索，并明确谁有权确认最终专业结论。

### 4.3 Account Pack：账号战略与人格层

每个账号单独定义：

- 品牌和账号关系；
- 目标用户；
- 用户的具体处境和问题；
- 内容支柱及比例；
- 创作者身份、真实经历与表达边界；
- 账号语气、语言风格和不使用的表达；
- 当前商业阶段；
- CTA 原则；
- 平台组合和发布节奏；
- 视觉识别、署名、固定片尾和品牌资产；
- 成功指标和当前待验证问题。

账号包不能凭空制造人设或专业身份。创作者人格必须来自真实经历、能力和价值观。

### 4.4 Channel Adapter：媒介翻译层

每种媒介单独定义：

- 用户在该平台上的使用场景；
- 内容长度、结构和节奏；
- 标题、封面和开场规则；
- 图片、音频、视频和字幕规格；
- 平台原生表达习惯；
- 来源、限制和免责声明如何保留；
- CTA 和互动方式；
- 发布检查清单；
- 与其他平台版本之间的一致性规则。

渠道适配器负责重新组织表达，不负责重新决定事实。

### 4.5 Episode Workspace：单期运行层

每个核心主题拥有独立、可追踪的工作区，至少包含：

- 唯一 Content ID；
- 选题任务书；
- 研究问题与证据包；
- 统一内容包；
- 叙事底稿；
- 公众号母稿；
- 图文方案与资产；
- 播客方案与资产；
- 视频方案与资产；
- 审核记录；
- 发布版本和链接；
- 用户反馈与复盘；
- 进入下一期或领域知识包的有效学习。

不同账号、不同领域和不同期次必须使用清晰命名空间，避免知识、品牌素材、平台凭据和用户数据相互污染。

### 4.6 每个 Agent 的四区边界

未来接入 Harness 的每个 Agent，都必须把以下内容分开：

1. **交互与输入区**：人提供的零散信息、链接、临时要求和待处理问题；
2. **学习与融合区**：从反馈和运行中提炼出的规则候选、合并决定与验证结果；
3. **系统与规范区**：已经确认、长期生效的职责、输入输出契约、规则、模板和边界；
4. **运行产出区**：单次任务产生的草稿、评分、费用、状态、审批和复盘。

允许的流转是：

```text
交互与输入
  → 提炼为学习候选
  → 人工确认或多轮验证
  → 合并进系统与规范

系统与规范 + 本轮输入
  → 生成运行产出
  → 反馈只能回到学习候选，不能直接改写系统
```

不得把完整聊天记录、单次运行结果或高播放量内容直接写成长期规则。Harness 组合多个 Agent 时，通过明确的输入输出契约、状态和版本交接，不共享一份边界不清的“大记忆”。每次系统规则变化必须记录来源、原因、影响范围、批准状态和验证结果。

## 五、第一套内容工作流

### 5.1 总体流程

```text
用户问题、内容支柱、研究线索和历史反馈
  ↓
选题 Agent
  ↓
选题任务书
  ↓
G1：人工选题批准
  ↓
研究与证据整理
  ↓
写作 Agent
  ↓
统一内容包 + 叙事底稿 + 公众号母稿
  ↓
G2：事实、证据、边界和表达审核
  ↓
G3：统一内容包锁定
  ↓
图文 Skill ─┬─ 播客 Skill ─┬─ 视频 Skill
            └──── 可并行适配 ────┘
  ↓
跨媒介一致性与专业边界检查
  ↓
G4：人工发布批准
  ↓
发布、互动、反馈采集
  ↓
复盘并回流选题池、账号包和领域包
```

统一内容包锁定、叙事底稿完成创作者确认后，公众号、图文、播客和视频原则上并行，不让一种媒介成为其他媒介不必要的前置依赖。

### 5.2 选题 Agent

#### 输入

- 当前内容支柱和建议比例；
- 目标用户及其具体问题；
- 评论、私信、访谈和历史反馈；
- 创作者真实经历和当前关注；
- 近期权威资料、研究线索和公共议题；
- 已发布内容、重复情况和表现；
- 本周可投入时间与生产能力；
- 领域风险和资质边界。

#### 输出

每个候选选题至少包含：

- 对外选题方向；
- 目标用户；
- 具体使用场景或困境；
- 本期核心问题；
- 一句话用户价值；
- 初步核心结论；
- 需要核验的关键事实；
- 适合引用的创作者经历；
- 本期待验证的用户问题；
- 可适配媒介；
- 风险等级；
- 制作成本；
- 推荐理由和不做的理由。

#### 最关键的部分

选题不是生成吸睛标题，而是决定本周值得投入研究和创作资源的用户问题。选题必须兼顾真实价值、证据可得性、创作者表达资格、媒介适配性、反馈价值和制作成本。

#### 退回条件

- 用户问题过于宽泛；
- 只能依赖热点、恐惧或夸张成立；
- 没有足够可靠的信息来源；
- 创作者没有真实表达基础；
- 必须越过专业边界才能给出有用结论；
- 与近期内容重复却没有新的用户价值；
- 生产成本超出当前可持续节奏。

### 5.3 研究与证据整理

研究是所有健康内容的底层步骤，不能因为某期不是论文解读就省略。

#### 输出

- 研究问题列表；
- 核心来源及发布日期；
- 来源优先级和证据类型；
- 支持哪些结论；
- 不支持哪些结论；
- 适用人群；
- 主要限制和不确定性；
- 相关性与因果性的区分；
- 相对风险与绝对风险的区分；
- 需要专业人员确认的内容；
- 发布前需要重新核验的时效信息。

#### 最关键的部分

研究材料的任务不是为预设观点找证据，而是决定哪些话能够说、能够说到什么程度，以及哪些问题仍然不能回答。

### 5.4 写作 Agent 与公众号 Skill

#### 输入

- 已批准的选题任务书；
- 研究与证据包；
- 账号包；
- 创作者提供的真实经历和观点；
- 文章规格；
- 医疗、隐私和专业审核边界。

#### 输出

- 统一内容包；
- 叙事底稿；
- 公众号标题候选；
- 文章结构；
- 完整公众号母稿；
- 关键结论与来源对应表；
- 风险表达和待审核项；
- 后续媒介可复用的故事、案例、框架、金句和视觉点；
- 自然互动问题。

#### 最关键的部分

统一内容包负责事实与逻辑，叙事底稿负责共享表达，公众号 Skill 负责长文适配。公众号文章要真正解决一个具体问题，但不成为其他媒介的母稿或事实源。语言流畅不能掩盖证据不足，故事不能取代事实，结论不能超出来源。

### 5.5 统一内容包锁定

统一内容包在进入多媒介加工前必须锁定版本。锁定意味着：

- 核心结论已经批准；
- 来源已经核验；
- 事实、观点和推断已经区分；
- 适用范围和限制已经明确；
- 不得出现的表达已经列出；
- 最终导向和互动问题已经确认；
- 所需专业审核已经完成，或内容已收缩至允许范围。

锁定后如需改变核心事实或结论，必须形成新版本，并让受影响的所有媒介产物重新检查。

### 5.6 图文制作 Agent

#### 输入

- 已锁定的统一内容包；
- 已确认的叙事底稿；
- 小红书或公众号图文规格；
- 账号视觉系统；
- 图片版权、隐私和平台规则。

#### 输出

- 图文目标和用户获得感；
- 封面标题候选；
- 一般为 8—9 页的分页结构；内容自然收束时可以调整，但不得为凑页数重复；
- 每页文案；
- 图表、插图、照片或视觉隐喻说明；
- 图片生成或设计提示；
- 逐页最终图片与可编辑排版源；
- 整组预览和手机阅读质检；
- 发布正文和互动问题；
- 来源、限制和必要说明的呈现位置；
- 视觉资产清单和质检结果。

#### 最关键的部分

图文不是把长文切成截图，而是围绕一个可以快速理解、值得收藏或转发的框架重新组织信息，同时不能为了简短删掉改变结论性质的限制。

### 5.7 播客制作 Agent

#### 输入

- 已锁定的统一内容包；
- 已确认的叙事底稿；
- 创作者口语习惯；
- 节目时长和节目定位；
- 可使用的故事、现场感和延展材料。

#### 输出

- 本期播客定位；
- 开场；
- 分段提纲和时间分配；
- 口语化主持稿或详细 Run of Show；
- 自然过渡；
- 需要原声强调的结论、来源与限制；
- 收口和互动问题；
- 节目标题、简介和 Show Notes；
- 后期剪辑、音乐和音效说明；
- 可截取的音频片段。

#### 最关键的部分

播客不能直接朗读公众号文章。它要利用声音建立人格、陪伴感和思考过程，同时保持与统一内容包一致。

### 5.8 视频制作 Agent

视频制作 Agent 作为一个视频导演和内部编排者。初期不为每个细节建立独立 Agent，先使用以下四个内部模块；当真实生产证明某个模块是稳定瓶颈后，再拆成子 Agent。

#### A. 视频策略模块

负责：

- 视频面向谁；
- 只传递什么核心结论；
- 视频整体导向；
- 最终落点；
- 长视频、短视频或两者组合；
- 目标时长；
- 用户看完后的合理动作；
- 哪些信息必须保留，哪些可以删减。

最关键的是一条视频只承担清楚、可完成的任务，不能为了复用把整篇长文压进一条短视频。

#### B. 钩子与脚本结构模块

负责：

- 前 3 秒钩子的多个候选；
- 钩子与实际内容承诺的一致性；
- 整体结构和时间轴；
- 困境、冲突、故事、框架、证据、限制和行动的顺序；
- 拉取用户信任的话术；
- 自然引导关注的话术；
- 话题收口方式；
- 长视频中适合切片的段落。

最关键的是钩子必须是内容真实价值的高密度表达，不能依赖疾病恐惧、夸大风险、虚假悬念或超出证据的承诺。

#### C. 视觉与制作模块

负责：

- 视频封面设计；
- 标题与封面文案的配合；
- 镜头表；
- A-roll、B-roll、图表、插图和演示素材；
- 字幕重点；
- 画面节奏；
- 拍摄清单；
- 品牌标识；
- 包含账号信息的固定片尾；
- 不同平台的尺寸和导出规格。

最关键的是视觉为理解和信任服务，不制造与正文不一致的暗示。

#### D. 成片质检模块

负责检查：

- 封面和标题是否夸大；
- 前 3 秒是否兑现；
- 核心结论是否被剪辑改变；
- 关键限制是否丢失；
- 长短版本是否断章取义；
- 字幕、数字、引文和账号信息是否准确；
- 时长是否符合目标；
- 片尾和互动动作是否完整；
- 是否存在版权、隐私、医疗或平台风险。

### 5.9 跨媒介一致性检查

图文、播客和视频完成后，应与锁定的统一内容包逐项核对：

- 核心事实是否一致；
- 结论强度是否一致；
- 是否保留必要限制；
- 是否新增未经研究支持的说法；
- 是否混淆事实、创作者观点和项目推断；
- CTA 是否符合当前商业阶段；
- 品牌身份和专业身份是否准确；
- 不同版本是否出现互相矛盾的数字、日期或行动建议。

一致不代表逐字相同。不同媒介应当原生表达，但不能产生新的事实版本。

### 5.10 发布、互动和复盘

发布后至少记录：

- 平台、版本、发布时间和链接；
- 制作时间和人工修改时间；
- 收藏、转发和完整观看等平台数据；
- 高质量评论和真实问题；
- 哪一句话促使用户描述自己的处境；
- 用户反复出现的困难；
- 哪些内容高流量但低价值；
- 哪些内容流量有限但带来高质量关系；
- 本期待验证问题的结果；
- 本期错误、返工和遗漏；
- 值得进入选题池、账号包或领域包的学习。

最关键的是把用户反馈转化为下一轮输入，而不是让工作流止于发布。

## 六、人工审核门与责任

### G1：选题批准

由创作者确认本周是否值得做、是否符合项目方向和当前能力。健康内容还必须按[平台健康内容审查链](../compliance/platform-health-content-review-chain.md)确认 H0—H3 类型、目标平台账号资质及是否触发专业或广告阻断。选题 Agent 只能提出建议，不能自动占用本周创作资源。

### G2：事实、证据和专业边界审核

确认关键结论能够回到来源，证据与结论匹配，并完成必要的专业审核。涉及疾病预防、诊断、治疗、康复或其他专业医学结论时，必须同时遵守账号平台资质和对应专业责任要求；商业、导流、交易和 AI 生成／合成内容分别完成广告性质与标识复核。

### G3：统一内容包锁定

确认本期唯一事实基准及版本。之后的 Agent 不得绕过这个版本自行扩展结论。

### G4：发布批准

检查最终标题、封面、正文、音频、视频、CTA、来源和免责声明，并覆盖账号资料、标签、字幕、画面文字、评论、私信、链接、二维码、商品组件、账号认证和发布当日平台规则。第一套工作流的所有公开内容都必须由人最终批准，不自动发布。

### 风险分级

- **低风险**：品牌建设、创作复盘、一般信息整理方法。规则检查后由创作者批准。
- **中风险**：涉及健康证据、公共健康建议、研究解读或专业资源信息。需要独立事实与边界复核。
- **高风险**：涉及疾病预防、诊断、治疗、用药、康复或可能被理解为个体医疗判断。专业医疗科普必须同时确认目标平台账号准入和对应领域专业责任；个体医疗判断禁止。无法满足时缩小至健康素养与信息整理，或停止发布。

最终责任不能转移给模型、Prompt 或自动化系统。

## 七、状态、版本和可追溯性

### 7.1 建议状态

```text
idea
→ topic_review
→ topic_approved
→ research
→ article_draft
→ evidence_review
→ canonical_locked
→ adaptations_in_progress
→ publish_review
→ approved
→ published
→ retrospective
→ archived
```

允许出现：

```text
changes_requested
NeedsEvidence
NeedsPlatformQualification
NeedsProfessionalReview
NeedsAdvertisingReview
Blocked
cancelled
```

### 7.2 版本要求

至少记录：

- Content ID；
- 统一内容包版本；
- 各媒介产物版本；
- 所使用的账号包、领域包和渠道适配器版本；
- 主要 Prompt 或工作流版本；
- 来源核验日期；
- 审核人和批准时间；
- 修改原因；
- 哪些下游产物受到修改影响。

### 7.3 不可覆盖的记录

以下信息不能只保留最终结果：

- 人工驳回原因；
- Agent 失败和返工原因；
- 事实或引用被纠正的记录；
- 高风险表达被删除的原因；
- 发布后发现的错误及修正；
- 用户反馈如何改变下一期或规则。

这些记录是未来抽取 Harness 和建立评估集的主要证据。

## 八、Agent 完成标准

每个 Agent 的输出都应有 Definition of Done。通用检查至少包括：

- 输入完整；
- 输出结构完整；
- 关键事实有来源；
- 没有超出允许范围；
- 不确定性被保留；
- 与上游版本一致；
- 明确列出仍需人工判断的事项；
- 资产和文件可被下游直接使用；
- 失败时明确指出缺少什么，而不是猜测补齐；
- 没有自动发布或产生未经批准的外部行动。

“生成了一份内容”不等于完成。只有下游能够可靠接收、审核和继续处理，才算完成。

## 九、质量评估体系

Harness 需要同时评估结果质量和过程质量。

### 9.1 结果质量

- 事实准确性；
- 来源可追溯性；
- 证据忠实度；
- 结论与限制匹配；
- 用户独立获得感；
- 账号人格一致性；
- 平台原生表达；
- 标题、封面和正文一致；
- 专业与合规边界；
- 跨媒介一致性。

### 9.2 过程质量

- 单期总耗时；
- 每个阶段的等待和返工；
- 人工修改比例；
- Agent 失败类型；
- 来源重新核验成本；
- 是否按承诺节奏完成；
- 哪些工作真正复用，哪些仍然重复制作；
- 人工审核是否成为不可持续瓶颈；
- 工作流是否保护创作者的健康、时间和长期节奏。

### 9.3 评估集

在真实运行中逐步积累：

- 优秀成品样例；
- 常见错误样例；
- 夸大标题反例；
- 证据不足反例；
- 越过专业边界反例；
- 跨媒介失真反例；
- 人工修改前后对照；
- 不同领域的专用测试题。

评估集应来自真实生产问题，不只依靠人为设想。

## 十、Harness 工程的分阶段实现

### 阶段 0：先把规则写清楚

#### 主要工作

- 确认本纲领；
- 定义统一内容包；
- 定义选题／写作 Agent 与各渠道 Skill 的输入输出契约；
- 定义审核门和风险分级；
- 定义 Content ID、文件结构、状态和版本规则；
- 定义第一版完成标准和复盘模板。

#### 最关键的部分

不要带着未解决的职责冲突开始自动化。先确定谁决定事实、谁能够修改、谁负责审核、什么情况下必须停止。

### 阶段 1：人工编排的健年 MVP

#### 主要工作

- 用文件、模板和明确 Prompt 运行流程；
- 每周只做一个核心主题；
- 统一内容包锁定、叙事底稿确认后，并行加工公众号、图文、播客和视频；
- 所有外部发布由人批准；
- 记录每次人工修改、返工和耗时；
- 暂不建设重型平台、自动发布和复杂多账号系统。

#### 最关键的部分

先证明这套方法能够稳定生产准确、有价值、可持续的内容。这个阶段的目标是学习真实流程，不是展示自动化程度。

### 阶段 2：半自动编排和质量稳定

#### 进入条件

- Agent 契约已经基本稳定；
- 主要返工原因已被识别；
- 统一内容包结构能够覆盖真实内容；
- 审核门没有频繁发生职责争议；
- 手工状态管理开始形成明确重复负担。

#### 主要工作

- 自动创建单期工作区；
- 自动传递已批准版本；
- 支持并行任务、失败重试和状态恢复；
- 自动执行结构、来源、版本和一致性检查；
- 形成审核队列；
- 汇总耗时、返工和发布反馈；
- 保持人类批准门。

#### 最关键的部分

自动化确定、重复、低风险的工作，不自动化仍然依赖专业判断和创作者责任的部分。

### 阶段 3：抽取 Harness Core

#### 建议启动门槛

不以发布数量作为唯一标准。建议至少满足：

- 已完成不少于 8 个端到端核心主题；
- 覆盖至少 3 个内容支柱和 3 种媒介；
- 最近 4 个主题没有发生底层流程重构；
- 主要人工修改和前 10 类返工原因已经分类；
- 能明确区分通用规则、健康领域规则和账号人格规则；
- 没有未解决的严重专业或合规问题；
- 已有可用于回归检查的优秀样例和反例；
- 第二个账号或领域已经有明确、真实的使用需求。

上述数字是建议门槛，不是为了赶进度而完成的形式指标；如果流程仍不稳定，应继续留在前一阶段。

#### 主要工作

- 抽取通用对象、状态机、审计和评估能力；
- 将健康规则移入 Domain Pack；
- 将多活十年 Lab 的定位和语气移入 Account Pack；
- 将公众号、图文、播客和视频规则移入 Channel Adapter；
- 保持第一套流程仍能运行；
- 为第二个账号建立最小配置。

#### 最关键的部分

抽取已经被两个真实场景需要的共性，而不是把所有差异都提前做成配置项。

### 阶段 4：第二账号验证

#### 主要工作

- 选择一个真实、边界清楚的新账号；
- 从新的 Domain Pack 和 Account Pack 开始配置；
- 不复制健年的专业结论和人格；
- 记录哪些所谓通用规则实际上只适用于健年；
- 检查内容、知识、资产、凭据和数据隔离；
- 比较使用 Harness 与从零建设的时间和质量。

#### 最关键的部分

第二账号的任务不是证明原设计正确，而是主动暴露错误抽象。发现不通用时应修正边界，不要求新账号适应旧系统。

### 阶段 5：多账号规模化

#### 进入条件

- Harness 已经支持至少两个差异明显的真实账号；
- 通用层和领域层边界稳定；
- 有可靠的权限、密钥和数据隔离；
- 有跨账号质量监控和成本记录；
- 专业审核资源能够匹配产量；
- 新账号仍然拥有明确用户价值和真实责任人。

#### 主要工作

- 建立账号创建和领域包维护流程；
- 建立版本兼容和升级机制；
- 建立跨账号但不泄露内容的通用评估；
- 建立模型、生成、审核和制作成本预算；
- 建立停更、暂停和归档机制；
- 控制账号数量，避免生产能力超过审核、互动和运营能力。

#### 最关键的部分

规模上限由专业责任、审核、互动和用户价值决定，不由模型生成速度决定。

## 十一、多账号复制的硬边界

### 11.1 知识隔离

不同领域的来源、术语、结论和风险规则分别管理。不能因为某个说法在一个领域包中存在，就被另一个账号自动调用。

### 11.2 品牌与人格隔离

每个账号有独立的目标用户、语言风格、视觉系统、CTA 和创作者身份。不得批量生成虚构人设或复制同一种人格。

### 11.3 数据与凭据隔离

平台账号、密钥、发布权限、用户反馈、私信和分析数据按账号隔离。最小权限访问，不让普通生产 Agent 获得不必要的发布权或用户敏感数据。

### 11.4 专业责任隔离

每个领域明确最终责任人和专业审核资源。一个领域的专业审核不能默认覆盖另一个领域。

### 11.5 工作流可配置

健年当前以公众号长文优先，但通用 Harness 应允许其他账号采用研究简报、访谈逐字稿、视频脚本、视觉故事板或其他内容对象作为首个主表达形式。

## 十二、明确不做什么

在第一套工作流没有跑顺前，不做：

- 重型多账号后台；
- 全自动选题、创作和发布；
- 为每个视频细节建立独立微型 Agent；
- 大规模账号矩阵；
- 复杂插件生态；
- 为尚未出现的需求设计大量配置项；
- 自动生成专业身份；
- 用播放量替代用户价值和信任；
- 用 AI 自审替代独立专业审核；
- 把用户病历、身份信息或可识别健康资料放入内容知识库；
- 为了提高产量降低证据、隐私和专业边界。

## 十三、关键成功标准

### 第一阶段成功

- 创作者能够按可持续节奏稳定完成核心主题；
- 选题／写作 Agent 与各渠道 Skill 交接清楚；
- 统一内容包能够可靠支撑不同媒介；
- 人工返工逐步减少且原因可解释；
- 公开内容没有严重事实、专业或边界问题；
- 内容带来高质量问题和真实互动；
- 工作流没有挤压健康、休息和其他明确优先级。

### Harness 抽取成功

- 新账号主要通过替换领域包和账号包启动；
- 通用 Core 不需要复制或大幅修改；
- 新账号不会继承健年的专业结论和人格；
- 不同账号保持事实、资产、凭据和数据隔离；
- 质量不因吞吐量增加而系统性下降；
- 审核责任始终清楚；
- 第二账号能够反向帮助修正通用设计。

### 规模化成功

- 每个账号都服务一个真实、明确的用户问题；
- 每个账号都有可验证的专业基础和责任人；
- 内容生产、审核、发布、互动和复盘能力匹配；
- Harness 降低重复劳动，但没有抹平领域差异；
- 账号数量增长没有超出团队的质量控制和用户关系能力。

## 十四、后续推进顺序

后续按以下顺序逐项落地：

1. 定义统一内容包模板；
2. 定义 Content ID、单期目录和状态；
3. 定义选题 Agent 契约；
4. 定义研究与证据包；
5. 定义写作 Agent 契约和公众号渠道 Skill；
6. 定义统一内容包锁定和变更规则；
7. 定义图文 Agent 契约；
8. 定义播客 Agent 契约；
9. 定义视频 Agent 及其内部四个模块；
10. 定义跨媒介一致性检查；
11. 定义人工审核门、风险分级和发布检查；
12. 定义单期复盘和反馈回流模板；
13. 选择第一个真实选题，人工跑通端到端流程；
14. 连续运行并记录返工、耗时和质量问题；
15. 只自动化已经稳定、重复、低风险的步骤；
16. 达到抽取门槛后再设计独立 Harness Core；
17. 用第二个真实账号验证通用性；
18. 验证成功后再讨论多账号规模化。

## 十五、一句话纲领

> 先用健年跑通一套真实、准确、有责任边界、创作者能够长期坚持的内容生产工作流；再从真实运行中抽取通用 Harness，以统一内容对象、明确 Agent 契约、独立审核门和反馈闭环复制生产能力，同时让每个领域保留自己的专业知识、责任体系和账号人格。
